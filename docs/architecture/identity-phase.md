# Identity phase status

Identity is **incomplete and disabled**. No login, registration, settings, or authorization HTTP route is wired, and the existing SSR settings preview remains unchanged. No billing changes were made. The domain primitives and repository are not a complete authentication system and must not be used as an authorization boundary until integrated and reviewed.

`020_identity` depends on `000_schema_ledger`; selecting it skips `010_catalog`, consistent with the V4 dependency DAG. The runner refuses an existing identity table before identity DDL; it may already have created the ledger. Migration is untested against MySQL 8 and no migration was applied. FKs: `user_roles` → users, roles and assigning user; `role_permissions` → roles and permissions; `sessions`, `email_verification_tokens`, `password_resets`, and `settings` → users; `audit_logs.actor_user_id` → users. Constraints and indexes are defined in the migration but not verified in a real target database. Settings currently cover owner-scoped rows only; global settings and a complete approved settings contract remain open.

The repository looks up active users and unexpired non-revoked sessions, resolves permissions, atomically audits session creation/revocation and versioned owner-scoped updates. Its caller must validate input, establish the authenticated owner, enforce permission checks, HTTPS, session cookie security, CSRF and Origin, rate limits, and safe errors. It does not create accounts, initialize settings, enforce verification, rotate session cookies, or implement recovery. Password reset/verification tables do not mean those flows are operational. Audit immutability is not enforced by DB privileges in this change. No seed role or permission grants exist.

Before enabling identity, implement service/repository interfaces, SSR and API controllers/forms, registration and login throttling, fixation-resistant session rotation, secure HttpOnly SameSite cookies, revocation/logout, CSRF and Origin checks, owner/RBAC middleware, approved settings validation and optimistic conflict handling, account verification/recovery where supported, and security-safe audit coverage. Run MySQL 8 fresh/upgrade/FK/transaction/concurrency tests and end-to-end session, fixation, CSRF, authorization, throttling and regression tests. Verify the actual target database and perform independent security review. Do not claim the preview `access=pro` parameter is an entitlement.

Rollback: no migration was applied. Remove only the new identity files and revert the runner's identity target when explicitly rolling back this work; preserve other working-tree changes. If a future migration is applied, stop writers and use a tested backup/forward-repair plan; MySQL DDL may implicitly commit. Restart with target schema and ledger introspection and a controlled MySQL 8 test environment.
